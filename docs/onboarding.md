# 처음 실행하는 사람을 위한 안내

이 문서는 이 저장소를 처음 받은 사람이 자기 맥에 기기를 연결해서 테스트를 실행하고, 그 결과를 로컬 웹페이지로 확인하기까지의 과정을 담았습니다.

## 준비하기 전에 받아야 하는 것

**아래 두 가지는 저장소에 들어 있지 않으므로 담당자에게 받아야 합니다.** 저장소가 공개 상태여서 내부 식별자와 앱 바이너리를 담지 않기 때문입니다.

| 필요한 것 | 설명 |
| --- | --- |
| `APP_ID` 값 | 테스트 대상 앱의 패키지 이름입니다. `.env` 에 넣습니다 |
| 대상 앱(APK) | 테스트할 빌드입니다. 이 저장소는 앱 설치를 담당하지 않습니다 |

테스트 계정 정보는 받을 필요가 없습니다. 현재 플로우는 게스트 로그인만 다루므로 계정을 쓰지 않습니다.

## 1. 저장소를 받고 준비 스크립트를 실행합니다

```bash
git clone https://github.com/seokjunjin/sdktest-maestro.git
cd sdktest-maestro
./scripts/setup.sh
```

`setup.sh` 가 다음을 확인하고 처리합니다.

- **Maestro CLI**: 없으면 공식 설치 스크립트로 설치합니다. 홈 디렉터리(`~/.maestro`)에만 설치되며 관리자 암호가 필요하지 않습니다.
- **Java 17 이상, adb, python3**: 설치되어 있는지 확인하고, 없으면 설치 명령을 안내합니다. 이 세 가지는 설치 위치와 방식이 환경마다 달라서 기존 개발 환경을 건드리지 않도록 자동으로 설치하지 않습니다.
- **`.env`**: 없으면 `APP_ID` 와 `SDK_ENV` 를 물어서 만들어 줍니다. 값을 미리 알고 있다면 인자로 넘길 수도 있습니다.

```bash
./scripts/setup.sh --app-id com.example.game --sdk-env qa
```

준비되지 않은 항목이 있으면 종료 코드 1 로 알려 줍니다. 안내를 따라 조치한 뒤 다시 실행하면 이미 준비된 항목은 건너뜁니다.

새 터미널에서도 `maestro` 명령을 쓰려면 아래 한 줄을 `~/.zprofile` 에 추가하세요.

```bash
export PATH="$PATH:$HOME/.maestro/bin"
```

## 2. 기기를 준비합니다

1. 받은 APK 를 기기에 설치합니다. `adb install -r <파일>.apk` 로 설치할 수 있습니다.
2. 기기를 USB 로 연결합니다.
3. 개발자 옵션에서 **USB 디버깅**을 켭니다.
4. 기기 화면에 **USB 디버깅 허용** 대화상자가 뜨면 허용을 누릅니다. 이때 "이 컴퓨터에서 항상 허용" 을 체크해 두면 다음부터 묻지 않습니다.
5. **화면 잠금을 해제해 둡니다.** 잠긴 상태에서는 앱이 전면에 올라오지 못해 테스트가 실패합니다.

준비가 되었는지 아래 명령으로 점검합니다.

```bash
./scripts/doctor.sh
```

기기가 `unauthorized` 상태이면 4 번 단계의 대화상자를 처리하지 않은 것입니다. 이 경우 점검이 실패로 알려 주며, 대화상자가 보이지 않으면 `adb kill-server` 를 실행한 뒤 케이블을 다시 연결하세요.

## 3. 테스트를 실행합니다

```bash
./scripts/run.sh
```

실행이 끝나면 `reports/<실행 시각>/` 폴더에 JUnit 결과와 로그, 스크린샷이 저장되고 `reports/index.html` 이 만들어집니다.

```bash
open reports/index.html
```

단계마다 붙는 스크린샷 링크까지 따라가려면 간단한 정적 서버를 띄우는 편이 편합니다.

```bash
cd reports && python3 -m http.server 8777 --bind 127.0.0.1
# 브라우저에서 http://127.0.0.1:8777 을 엽니다
```

## 기기에 따라 달라지는 부분

**화면 비율이 다른 기기에서는 결과가 달라질 수 있습니다.** DevPlay SDK Configuration 화면은 Unity 로 렌더링되어 뷰 계층에 요소가 노출되지 않아서, 그 화면의 조작만 백분율 좌표로 되어 있습니다. 이 좌표는 세로 방향 19.5:9 단말(예: 1080x2340)에서 측정한 값입니다.

비율이 크게 다른 기기, 특히 태블릿에서는 좌표가 어긋납니다. 이때 나타나는 결과는 두 가지입니다.

- **Start 버튼 탭이 빗나가면** 게임이 기동하지 않아 다음 단계가 시간 초과로 실패합니다.
- **나머지 좌표가 빗나가면** 실패로 드러나지 않고, 의도한 환경이 아닌 곳에서 테스트가 통과합니다. 환경이 QA 가 아니라 Dev 로, 접속 서버가 Clone 이 아니라 Origin 으로 설정된 채 통과할 수 있습니다.

두 번째가 더 위험하므로, **측정 기준과 다른 비율의 기기를 쓰신다면 결과 페이지에서 SDK Configuration 화면의 스크린샷을 직접 확인해 주세요.** 증적으로 남아 있습니다.

## 결과 페이지는 각자의 것입니다

`reports/` 는 커밋 대상이 아니므로, **결과 페이지에는 자기 컴퓨터에서 실행한 이력만 쌓입니다.** 여러 사람의 실행을 한 페이지에 모으는 기능은 아직 없습니다.

사내에 공유된 링크(`a.teamdev.ai`)는 Pantry 아티팩트로 올린 것이고, 아티팩트는 올린 사람의 계정에 귀속됩니다. 다른 사람이 올리면 자기 계정 아래에 별개의 링크가 생깁니다. 공유 링크를 하나로 유지하려면 한 사람이 결과를 모아서 갱신하는 방식이 필요합니다.

## 막혔을 때

| 증상 | 확인할 것 |
| --- | --- |
| `maestro` 명령을 찾을 수 없습니다 | `export PATH="$PATH:$HOME/.maestro/bin"` 를 실행했는지 |
| 기기가 목록에 없습니다 | USB 디버깅을 켰는지, 허용 대화상자를 처리했는지 |
| 앱 실행 단계에서 시간 초과로 실패합니다 | 화면 잠금을 해제했는지, APK 가 설치되어 있는지 |
| 결과 페이지의 앱 버전이 비어 있습니다 | `adb` 가 있는지, 기기가 한 대만 연결되어 있는지 |
| 스크린샷 링크가 열리지 않습니다 | 파일을 직접 열지 않고 정적 서버로 열었는지 |

플로우를 새로 작성하거나 고치려면 [writing-flows.md](writing-flows.md) 를 읽어 주세요.
